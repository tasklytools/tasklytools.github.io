Encoding details

              

              
    
                
  • UTF-8 text is encoded by bytes, so accented letters, emoji, and non-Latin scripts round-trip correctly.
    • 
                
  • Files are read with the browser File API and encoded without being uploaded.
    • 
                
  • URL-safe mode replaces + with -, / with _, and removes trailing padding.
    • 
                
  • Base64 is not encryption. Anyone can decode it, so never use it to protect passwords or private data.
    •

What Base64 is used for

        
Base64 represents binary data using printable ASCII characters. It is commonly used in data URLs, email attachments, JSON payloads, authentication headers, and tokens. Encoding increases the data size by roughly one third, so it is not a compression method. It is also not encryption: Base64 is trivially reversible and provides no secrecy.


        
Standard and URL-safe Base64

        
Standard Base64 uses the characters + and /, and usually ends with = padding. URL-safe Base64 uses - and _ so the value can be placed in a URL or filename without escaping, and it often omits padding. This decoder accepts either alphabet, restores missing padding, and rejects values that mix the two alphabets. It also rejects invalid characters and impossible lengths instead of silently ignoring them.


        
Unicode and binary handling

        
Text is encoded as UTF-8 before Base64 conversion, which is why emoji and non-Latin characters survive the round trip. When decoding, the tool first tries strict UTF-8. If the bytes are not valid UTF-8, it does not invent replacement characters: it shows a hex preview and lets you download the original binary bytes. This is useful for images, PDFs, archives, and other files that are not meant to be read as text.


        
Common Base64 mistakes

        
    
          
  • Do not remove characters from the middle of a Base64 value to shorten it; decode the value or use a proper token format.
    • 
          
  • Do not assume a string is Base64 just because it contains letters and numbers. Validate its length, alphabet, and padding.
    • 
          
  • Do not paste secrets into random online services. This tool processes data locally, but always verify the privacy claims of any tool you use.
    • 
          
  • Remember that Base64 is not a substitute for encryption, hashing, or access control.
